# Контекст проекта «Синоникс-ассистент»

## Назначение

Локальный ИИ-ассистент для кейса АйТи Бастион на НЭТИ-НЕКСТ 2.0 помогает описать сети, системы и потоки, подобрать размещение «Синоникса», уточнить недостающие сведения и получить правила, объяснение и редактируемую схему draw.io. Источником предметных сведений служит база знаний в `kb/`. Подробные инструкции и примеры находятся в [README.md](README.md), исходный план — в [PLAN.md](PLAN.md); при расхождениях с планом актуальна реализация.

## Стек и запуск

TypeScript, Node.js (в плане указан Node 24), npm workspaces, Fastify, React 18, Vite и Vitest. Установка и разработка:

```bash
npm install
cp .env.example .env  # при необходимости заполнить ключи
npm run dev           # API :8787, интерфейс http://127.0.0.1:5173
```

Для локального production-режима: `npm run build`, затем `npm start` и открыть `http://127.0.0.1:8787`. Порт API задаётся `SYNONYX_PORT`. Проверки: `npm test`, `npm run typecheck`, `npm run build`. Скрипты `npm run examples`, `npm run kb -- "запрос"` и `npm run eval -- ...` генерируют примеры, ищут по базе и оценивают модели соответственно.

## Устройство и поток данных

1. React-интерфейс создаёт сессию и отправляет сообщение или ответы на карточки в Fastify API.
2. Для свободного текста слой `packages/llm` получает состояние, историю и найденные фрагменты базы; модель классифицирует намерение, извлекает операции `Op[]` и при необходимости отвечает по источникам. Ответ проверяется до применения к состоянию.
3. `packages/core` применяет операции и детерминированно вычисляет правила, уточнения, статус, объяснение и экспорт. Выбор готового ответа карточки обычно преобразуется в операции без обращения к модели; свободный вариант может потребовать модель.
4. `packages/diagram` строит draw.io XML из состояния и результата. Интерфейс показывает тот же XML и позволяет скачать схему; также доступны таблица и служебный JSON.
5. Сервер сохраняет сессии и журналы локально. Версия состояния используется для обнаружения конфликтов; доступен откат к предыдущему состоянию.

Контракты: `packages/core/src/types.ts` — состояние и результат; `ops.ts` — операции и преобразование ответов; `engine.ts` — расчёт; `questions.ts`, `explain.ts`, `export.ts` — вопросы, объяснение и JSON. `Maybe<T>` различает `null` (ещё не выяснено) и `'unknown'` (пользователь не знает). `packages/llm/src/validation.ts` проверяет ответ и ссылки модели; `apps/server/src/service.ts` координирует шаги и версии.

## Структура

- `apps/server/` — Fastify API, обработка сессий, файловое хранилище и тесты.
- `apps/web/` — React/Vite: чат, вопросы, результат, схема, источники и расходы.
- `packages/core/` — предметная модель, операции, правила и сценарии.
- `packages/llm/` — конфигурация, промпт, клиент совместимого API, извлечение и валидация.
- `packages/kb/` — индекс и поиск по базе знаний.
- `packages/diagram/` — раскладка и генерация XML draw.io.
- `kb/` — предметная документация, глоссарий, методика, эталоны и шаблоны схем.
- `config/` — настройки модели и кандидатов оценки; `examples/` — открытые примеры; `scripts/` — служебные команды.
- `data/` — локальные сессии и журналы, исключены из Git.

## Модели и база знаний

`config/models.json` содержит модель извлечения, адрес совместимого API, имя переменной ключа и снимок тарифов. В текущей конфигурации указан `deepseek/deepseek-v4.1-flash` через ProxyAPI; лимит входной цены — $0,10 за миллион токенов. Это конфигурационный снимок, а не гарантия текущих тарифов или доступности модели. Ключи задаются в `.env` (см. `.env.example`) и не коммитятся. Без настроенной модели свободный текст не разбирается; карточки, детерминированный расчёт и экспорт доступны.

Поиск по разделам Markdown в `kb/` использует BM25, сокращения и синонимы без эмбеддингов. Эталонный `04_benchmarks.json` не индексируется. Найденные фрагменты передаются модели, а ссылки проверяются сервером; без модели доступны выдержки из базы с источниками.

## API

- `GET /api/config` — конфигурация клиента.
- `POST /api/sessions`, `GET /api/sessions/:id` — создание и получение сессии.
- `POST /api/sessions/:id/messages` — сообщение `{text}`; `POST .../answers` — `{answers:[{questionId,value}]}`.
- `POST .../undo` — откат с `{expectedVersion}`; `POST .../timing` — время шага `{turnId,clientMs}`.
- `GET .../result.json`, `.../diagram.drawio`, `.../log.jsonl` — экспорт результата, схемы и журнала.
- `GET /api/vendor-requests` — пожелания разработчику продукта.
- `GET /api/kb/search?q=…&k=5`, `GET /api/kb/section?file=…&section=…` — поиск и раздел источника.
- В режиме разработки доступна загрузка подготовленных сценариев через `POST /api/sessions/:id/dev/scenario/:name`.

## Данные и проверка

Сессии хранятся в `data/sessions/*.json`; журналы вызовов, шагов и пожеланий — в `data/logs/`. Это локальное файловое хранение, не предназначенное само по себе для распределённого развёртывания. `node_modules/`, сборки, `.env`, данные и отчёты `examples/eval-*.json` исключены из Git. Тесты охватывают движок, поиск, схемы, валидацию модели и сервер. Для проверки реальной модели нужны доступный провайдер и действительный ключ; обычные локальные тесты этого не подтверждают.
