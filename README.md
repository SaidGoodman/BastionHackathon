# synonyx-assistant

ИИ-ассистент по размещению «Синоникса» (кейс АйТи Бастион, НЭТИ-НЕКСТ 2.0). План и распределение — [PLAN.md](PLAN.md).

## Запуск

```powershell
npm install
npm run dev       # сервер :8787 + интерфейс http://127.0.0.1:5173 (режим разработки: кнопки открытых сценариев без модели)
npm test          # тесты движка, схемы и сервера
npm run typecheck
```

Сборка для проверяющих: `npm run build`, затем `npm start` — интерфейс и API на http://127.0.0.1:8787.

Модель: заполнить `config/models.json` (id, ссылка на карточку OpenRouter, тарифы ≤ $0,10/млн на входе) и задать переменную `OPENROUTER_API_KEY`.
Без этого свободный текст не разбирается, но ответы на карточки вопросов, схема, таблица и экспорт работают.
Сервер проверяет лимит входного тарифа при старте. Порт сервера — `SYNONYX_PORT`.

## API

| Метод | Путь | Что |
|---|---|---|
| POST | `/api/sessions` | новая сессия |
| GET | `/api/sessions/:id` | состояние, результат, история, расходы |
| POST | `/api/sessions/:id/messages` | `{text}` — свободный текст (1 вызов модели) |
| POST | `/api/sessions/:id/answers` | `{answers:[{questionId, value}]}` — ответы на карточки (без модели; «другое» → модель) |
| POST | `/api/sessions/:id/timing` | `{turnId, clientMs}` — полное время шага до завершённой отрисовки |
| GET | `/api/sessions/:id/result.json` | служебный JSON для экспертной проверки |
| GET | `/api/sessions/:id/diagram.drawio` | актуальная схема |
| GET | `/api/sessions/:id/log.jsonl` | журнал вызовов моделей и шагов |
| GET | `/api/vendor-requests` | пожелания для разработчика продукта по всем сессиям |
| GET | `/api/kb/search?q=…&k=5` | поиск по базе знаний (отладка) |
| GET | `/api/kb/section?file=…&section=…` | текст раздела по ссылке-источнику (открывается по клику на источник) |

Журналы на диске: `data/logs/calls.jsonl`, `turns.jsonl`, `requests_for_vendor.jsonl`; сессии — `data/sessions/*.json`.

## Что где

| Путь | Что |
|---|---|
| `packages/core/src/types.ts` | **Контракт состояния**: сети, устройства, потоки данных/файлов, `Maybe<T>` (`null` — не выяснено, `'unknown'` — «не знаю») |
| `packages/core/src/ops.ts` | **Контракт операций** `Op[]` — формат ответа LLM-извлечения; `answerToOps` — клик по варианту ответа без модели |

| `packages/core/src/export.ts` | служебный JSON (совместим с `result.example.json`) |

| `packages/kb` | поиск по базе знаний (см. ниже) |

## Поиск по базе знаний (`packages/kb`)

- `kb/*.md` режутся на разделы по заголовкам; источник — «файл § раздел» в том же формате, что ссылки движка. `04_benchmarks.json` не индексируется: эталоны открытых сценариев не попадают в ответы.
- Поиск — BM25 по ключевым словам с лёгким отсечением окончаний, раскрытием сокращений («МЭ», «флешка», «Узел В») и синонимами. Без модели и эмбеддингов, поэтому в расходы сессии не входит.
- Справочник `01_scope_functions_synonyx_1.9.md` приоритетнее; разделы методики о порядке диалога и оформлении схемы в выдаче ниже — это инструкции ассистенту, а не факты о продукте.
- На каждое сообщение находятся 4 фрагмента и передаются модели вместе с состоянием. Модель отвечает на вопрос о продукте только по ним и называет id фрагментов; ссылку строит сервер, выдуманные id отбрасываются.
- Без модели вопрос о продукте получает дословные выдержки из найденных разделов с источниками.
- В интерфейсе любой источник (в чате, таблице правил, объяснении) открывает текст раздела.

```powershell
npm run kb -- "Сколько правил можно настроить на одном Синониксе?"
```

## Схема (`packages/diagram`)

```ts
import { toDrawio } from '@synonyx/diagram';
const xml = toDrawio(state, evaluate(state)); // содержимое файла .drawio (несжатый mxfile)
```

- Стили скопированы из `kb/06_template.drawio`, раскладка повторяет `kb/05_pattern_F02/F07.drawio`.
- Вход — `rule.ends` из движка: какие системы, ручная передача, USB и способ на каждой стороне правила.
- Слоты на узлах идут в том же порядке, что концы у карточек, и у каждого участка свой вертикальный канал — линии не пересекаются (проверяется тестом).
- В интерфейсе тот же XML показывает просмотрщик draw.io (`viewer-static.min.js`), поэтому картинка и скачиваемый файл совпадают.

```powershell
npm run examples   # examples/*.drawio, *.json, *.txt по открытым сценариям + preview.html / view-*.html
```
